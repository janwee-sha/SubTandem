# 契约：正文候选、混合主语言与翻译资格

## 输入与输出

沿用 [007 的输入、生命周期与等价契约](../../007-auto-language-support/contracts/language-detection.md)；候选接受、识别状态和指标按本契约及 [022 规格](../spec.md)。只接收当前窗口已解析的正文，不重新读文件，不使用文件名、容器标签或轨道 `lang` 作候选兜底。

```ts
interface LanguageDetectionInput {
  playerId: string;
  mediaEpoch: number;
  trackIdentity: string;
  contentHash: string;
  cues: readonly SubtitleCue[];
}

type LanguageDetectionResult =
  | { state: "reliable"; languageId: string }
  | { state: "unknown" }
  | { state: "unsupported" };
```

协调结果增加 `contentHash` 和 `attemptId`。`reliable` 的唯一含义是“已选定受支持正文候选”，不表示高置信度。不得将正文、候选列表、分数、原始元数据、路径或异常传播到 Sidebar、Global、日志或诊断。

## 正文与权重

1. 使用解析后的稳定正文顺序；cue 起止时间、ID、数量和显示时长不参与权重。检测专用清洗剥除格式标记和网址，将空白规范化，保持文字顺序及全部出现次数，不修改原始播放或待翻译正文。
2. 有效文字数按 NFC 规范化后 Unicode `Letter` 码点计；结合标记保留用于分类但不另计权重。排除空白、数字、符号、完整网址及格式标记中的文字。仅含这些内容时没有有效正文。
3. cue 边界不形成独立投票单元；按正文标点、词边界和文字预算建立不重叠归属片段，跨 cue 补足上下文。相同自然正文的分段变体应保持翻译资格；混合正文仅改变分段/时长应保持主语言，词内拆分、Han 换行也纳入配对回归。
4. 不超过总文字预算时全量分类；超过预算时，按有效文字位置均匀覆盖全轨，最多 64 个代表区间，每区间采样中心附近的有界正文。抽样片段的 `observedLetterCount` 总和不得超过所选总预算。按区间的实际有效文字量记录 `representedLetterCount`；分类上下文另受单调用上限约束，不得再次计权。此时语言量是抽样估计，验收不能免除超上限混合场景。
5. 每段得到语言归属后累计代表文字量。已有的不同语言候选不得因局部不一致被删除；整段/邻近上下文可帮助短片段排序，全轨候选仅补足无局部候选的片段。禁止用 cue 数、时长、模型分数或整轨第一名代替语言文字量。

## 候选与主语言

- 使用锁定 `franc` 模型，分类设置 `minLength: 0`。受支持查询仅使用附录 A 的 67 种明确映射；完整查询用于范围外证据。每次输入含上下文最多 2,048 UTF-16 单元，并在码点边界切分，避免模型静默截断。
- 移除 `MIN_CUES`、`MIN_LETTERS`、50 次幂分差、固定窗口个数及支持率对受支持候选的拒绝；少量正文、分差小、混合、罗马字或歌词都不构成 `unknown` 理由。
- 范围外确认作用于局部归属：只有正文文字系统不存在受支持语言，或完整模型对同一局部正文及其内容上下文给出一致范围外语言且满足校准证据规则时，才将该片段归为范围外。共享文字不能直接对应唯一语言。
- 不能把所有范围外语言合成一类争夺主语言；分别累计其稳定语言身份。确认不足时回到受支持最佳候选。不得要求范围外语言占全轨多数，40/35/25 的选择同样适用于已确认范围外的主语言。
- 文字系统只能确认范围外，不能凭空产生唯一语言身份；没有稳定身份的范围外文字单独记录为未归属量，不合成一个语言竞争者。全轨仅有已确认范围外的正文时可直接返回 `unsupported`。
- 主语言是累计文字量最大的语言。并列按规范语言 ID 的 Unicode 码点序选一个，不能依赖目标语言、目标目录顺序、locale 或随机数。主语言已确认范围外则 `unsupported`，否则返回受支持候选。
- 无有效文字、最终无任何候选、异常或超时才返回 `unknown`；不能因部分片段缺少候选拒绝其他片段已有的受支持候选。分母中保留未归属文字，不把其分配为零长度。
- 中文先以 `zh` 参加主语言比较，选中后仅用归属中文的正文判断形式。沿用至少三种独有形式字的证据方式，但剔除 `后/里/云` 等两种书写均可能使用的字；形式证据冲突或不足输出 `zh`，不返回 `unknown`。`shouldTranslate()` 的既有等价规则保持有效。

## 参数校准与冻结

下列有限搜索是实施阶段的确定工作，不把未知质量表现伪装成已经校准的数值。两套自然语料先按[语料契约](corpus-evaluation.md)冻结，再只使用校准集运行生产检测核心。

| 参数 | 校准候选或固定值 | 可影响的行为 |
| --- | --- | --- |
| 全量/抽样总预算 | 4,096、8,192、16,384 个有效文字 | 处理上限，不作为拒绝条件 |
| 内容片段预算 | 128、256、512 个有效文字 | 局部归属粒度，短片段照常处理 |
| 单次上下文上限 | 512、1,024、2,048 UTF-16 单元 | 候选排序证据，不能越过模型截断上限 |
| 范围外原始归一化分差 | 0.02、0.05、0.10 | 同次完整查询中范围外第一名与最佳受支持候选的分差；不做幂变换 |
| 范围外上下文一致性 | 当前段和可用上下文首选为同一范围外身份 | 只用于范围外确认，无固定最低 cue/窗口数量；不足则采用受支持候选 |
| 候选最短输入 | `minLength: 0`，固定 | 禁止依赖隐含字数门槛 |

先排除违反翻译资格、混合选择、生命周期或性能契约的配置；其余按校准集最差正样本长度组正确率、总体正确率、范围外行为正确率依次排序，仍相同时选更低计算预算及固定参数序。没有合格配置则停止校准交付并修订本规格设计，不能用拒绝候选换取通过。配置与依赖哈希在第一次冻结验收前保存；验收数据不能参与选择。

## 分片、期限与生命周期

生产检测核心暴露工作步骤；`detectSubtitleLanguage()` 的直接评估入口和 `LanguageDetectionCoordinator` 消费同一实现，测试不得另造算法。正文遍历、索引、取样、单次分类和聚合均为有界步骤；避免先全量拼接或排序再开始计时。

协调器以正文就绪时刻为起点设置 500 ms 总期限，在实际步骤之间让出事件循环，每步前后及提交前核验 `playerId + mediaEpoch + trackIdentity + contentHash + attemptId`。到期或剩余时间不足下一个步骤已验证的执行预算时，不再启动新工作；当前 attempt 提交一次 `unknown`，随后清理；过期 attempt 直接丢弃。单个分类调用不可被 JavaScript 定时器抢占，必须靠输入上限和实测分片预算保证最迟结束，不以返回前补查耗时冒充可中断执行。

换轨、换片、正文改变、禁用及关窗使工作失效；seek 保留同源结果，目标语言成功保存后复用同源候选重新门控。识别结束或失效即释放样本和证据；只保留当前会话所需结果。

| 结果 | 会话状态 | Provider 翻译调用 |
| --- | --- | --- |
| 检测进行中 | `detectingLanguage` | 0 |
| `unknown` | `languageUnrecognized` | 0 |
| `unsupported` | `languageUnsupported` | 0 |
| 已选候选与目标等价 | `noTranslationNeeded` | 0 |
| 已选候选与目标不等价 | 既有 `preparing/running` | 用户启用、Profile revision 可用且结果有效时进入翻译 |
| 迟到/已失效 | 不提交任何状态 | 0 |

保留当前英文文案与 Sidebar 结构，不显示置信度或算法名称。低置信度、混合或罗马字候选按同一条规则处理。调用仍仅发送当前位置附近必要字幕至已选择的 Profile revision；元数据绝不能通过 `ControllerSource.language` 绕过检测，集成测试必须从正式正文入口证明该边界。
