# 功能规格：SubTandem 双平台打赏入口

**功能标识**：`006-sponsor-entry`

**创建日期**：2026-08-14

**状态**：已澄清

**输入**：为 SubTandem 配置爱发电与 Ko-fi 打赏入口，统一使用“请创作者喝杯咖啡”的表达，并完成 Ko-fi 公开资料和一次性支持设置。

## 用户场景与测试

### 用户故事 1：从公开文档自愿支持项目（P1）

用户阅读任一语言的项目说明时，可以清楚找到爱发电和 Ko-fi 两个平台，并理解打赏完全自愿且不会获得额外产品权益。

**优先原因**：这是用户发现并进入打赏渠道的主要路径。

**独立测试**：打开任一语言的项目说明，确认两个规范链接均可见，边界声明完整；简体中文页面还可通过二维码进入爱发电。

**验收场景**：

1. **假如** 用户查看任一语言的项目说明，**当** 用户进入打赏区，**那么** 页面同时提供爱发电和 Ko-fi 链接，并表达“请创作者喝杯咖啡”。
2. **假如** 用户查看打赏说明，**当** 用户判断打赏所得权益，**那么** 页面明确说明 SubTandem 可免费完整使用，打赏不解锁功能、专属版本、优先翻译或模型额度。
3. **假如** 中文用户查看简体中文说明，**当** 用户使用移动设备扫码，**那么** 二维码可进入与文字链接一致的爱发电打赏页。

---

### 用户故事 2：从 GitHub Sponsor 发现打赏入口（P2）

用户可通过 GitHub Sponsor 按钮进入与 README 相同的两个打赏平台，且不同入口不会指向不同账号。

**优先原因**：该入口覆盖未完整阅读 README 的仓库访问者。

**独立测试**：检查仓库 Sponsor 配置，确认两个规范链接与 README 一致。

**验收场景**：

1. **假如** 用户访问仓库，**当** 用户打开 Sponsor 入口，**那么** 可选择爱发电或 Ko-fi。

---

### 用户故事 3：在 Ko-fi 以咖啡单位支持创作者（P3）

海外用户打开 Ko-fi 页面时，可以确认该页面用于支持 SubTandem，并按每杯 5 美元进行默认一次性支持。

**优先原因**：页面配置决定用户从仓库离开后看到的最终打赏体验。

**独立测试**：以公开访问者视角打开 Ko-fi 页面，核对项目描述、网站、Coffee 模式、单位价格、一次性默认值及感谢文案。

**验收场景**：

1. **假如** 用户打开 Ko-fi 页面，**当** 用户查看简介和网站，**那么** 页面说明可通过请 SubTandem 创作者喝咖啡支持项目，并链接到项目仓库。
2. **假如** 用户准备打赏，**当** 用户查看支持面板，**那么** 面板使用 Coffee 单位，单杯和最低金额均为 5 美元，并默认一次性支持。
3. **假如** 用户完成打赏，**当** 平台显示自动感谢信息，**那么** 信息感谢用户请创作者喝咖啡，并重申项目对所有人保持免费完整可用。

### 边界情况

- 任一入口链接失效或与规范链接不一致时，不得将该入口视为配置完成。
- 二维码无法识别或指向非规范爱发电页面时，必须替换资产后再验收。
- Ko-fi 要求地区合规信息时，只向 Ko-fi 提交用户确认的地区与邮编，不得将该信息写入仓库。
- 不进行真实付款作为验收；通过公开页面和已连接收款方式的状态确认配置。

## 需求

### 功能需求

- **FR-001**：所有项目说明 MUST 同时提供规范爱发电链接与 `https://ko-fi.com/ianhsia`。
- **FR-002**：所有项目说明 MUST 使用对应语言表达“请 SubTandem 创作者喝杯咖啡”，并声明免费完整使用、无额外权益、无模型额度以及 Provider 可能独立收费。
- **FR-003**：简体中文项目说明 MUST 展示可识别且指向规范爱发电页面的二维码，其他语言只需提供文字链接。
- **FR-004**：GitHub Sponsor 配置 MUST 同时公开 Ko-fi 用户名和规范爱发电链接。
- **FR-006**：仓库 MUST 以自动化测试验证 Sponsor 配置、全部项目说明和二维码引用的一致性。
- **FR-007**：Ko-fi 资料 MUST 保留展示名 `Ian` 与用户名 `ianhsia`，简介设为 `Support SubTandem by buying its creator a coffee.`，网站设为项目仓库。
- **FR-008**：Ko-fi MUST 使用 USD、Coffee metaphor、单位 `Coffee`、单杯 5 美元、最低 5 美元、`Tip` 按钮，并保持一次性支持为默认值。
- **FR-009**：Ko-fi 自动感谢文案 MUST 为 `Thank you for buying the SubTandem creator a coffee! SubTandem stays free and fully featured for everyone.`。
- **FR-010**：Ko-fi 地区合规信息 MUST 按用户确认设为 `United States` 及其确认的美国邮编，具体邮编不得进入版本控制或验证输出。
- **FR-011**：实现 MUST NOT 连接 Stripe、创建会员等级、商店或佣金服务，也 MUST NOT 执行真实付款。
- **FR-012**：爱发电认证说明和账户私密资料 MUST NOT 纳入版本控制；公开仓库地址作为后续爱发电创作者认证证明页面。
- **FR-013**：爱发电二维码 MUST 迁移到稳定的文档资产位置；迁移完成后临时 `docs/sponsor/` MUST 不再保留。

### 关键实体

- **打赏渠道**：平台名称、规范公开地址、面向受众和统一文案边界。
- **打赏入口**：README、二维码或 Sponsor 按钮中指向渠道的公开入口。
- **Ko-fi 页面设置**：公开资料、收款地区、币种、Coffee 单位、价格、按钮语义、默认频率和感谢文案。

## 成功标准

### 可衡量结果

- **SC-001**：7 份项目说明均提供两个规范平台入口，且 100% 包含对应语言的四项边界声明。
- **SC-002**：GitHub Sponsor 配置提供两个规范入口，自动化一致性检查全部通过。
- **SC-003**：爱发电二维码在至少一台移动设备上一次扫码成功，并进入与文字链接相同的页面。
- **SC-004**：公开 Ko-fi 页面核对的资料、地区、币种、Coffee 单位、金额、默认频率和感谢文案全部符合需求，无额外付费产品被启用。
- **SC-005**：仓库不包含邮编、支付账户、认证说明或其他私密账户资料，既有产品与发布检查保持通过。
