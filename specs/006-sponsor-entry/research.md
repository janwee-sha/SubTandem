# 调研结论：SubLingo 双平台打赏入口

## 渠道与规范地址

**决策**：爱发电使用临时资料中已提供的 item 链接，Ko-fi 使用 `https://ko-fi.com/ianhsia`；GitHub Sponsor 同时暴露两者。

**理由**：两个地址已经由用户创建并确认，分别覆盖中国大陆和海外用户，与现有互联网发布方案一致。

**备选**：只提供一个平台会降低可支付性；GitHub Sponsors 不适合作为当前默认渠道。

## README 与二维码

**决策**：七份 README 都增加本地化文字入口，只有简体中文 README 展示爱发电二维码；二维码迁移到 `docs/readme/assets/aifadian-sponsor.jpeg`。

**理由**：所有读者都可发现双平台，二维码主要服务国内移动支付场景；稳定资产目录便于引用和测试，也避免版本化认证说明。

**备选**：所有语言嵌入二维码会增加噪声；保留整个临时目录会把认证流程资料误当项目文档。

## Ko-fi 页面

**决策**：保留账号身份和 PayPal，填写项目简介与仓库网站，按用户确认的美国地区资料完成合规确认，使用 USD Coffee 模式，单杯和最低金额均为 5 美元，CTA 为 Tip，一次性支持默认，设置统一感谢文案。

**理由**：这是用户明确选择的账户所在地、金额与文案；Coffee 隐喻与爱发电二维码一致。

**备选**：Simple tip 与统一咖啡表达冲突；默认月度支持会改变一次性自愿打赏定位；Stripe、会员、商店和佣金超出范围。

## 外部副作用控制

**决策**：仓库改动和自动测试可直接执行；Ko-fi 表单在最终保存前展示精确摘要并取得一次即时确认。爱发电认证只准备公开证明入口，不代替用户提交后台认证。

**理由**：保存 Ko-fi 设置会修改外部账户，按浏览器安全约束必须在操作时确认；认证审批需要仓库公开状态且不是本次代码交付的必要条件。

**备选**：不经确认直接保存不符合外部副作用规则；提前提交认证无法提供已经公开的仓库证据。
