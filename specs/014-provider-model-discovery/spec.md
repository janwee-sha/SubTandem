# 功能规格：服务模型发现与凭据扩展

**功能目录**：`specs/014-provider-model-discovery`  
**创建日期**：2026-08-21  
**状态**：已完成

**输入**：将 OpenAI-compatible 服务类型的可见名称改为 OpenAI，保留自定义 Endpoint；为 Ollama 增加访问远程服务所需的 API Key；把两种服务的 Model ID 改为由服务端模型列表与可编辑自定义项组成的下拉列表，并支持自动、手动刷新。

## 用户场景与测试

### 用户故事 1：从服务实际返回的模型中选择（优先级：P1）

用户配置 OpenAI 或 Ollama Profile 时，希望直接看到当前 Endpoint 实际提供的模型，并从中选择 Model ID；如果目标模型未列出，仍可输入准确的自定义 Model ID。

**优先级理由**：模型标识填写错误会直接导致连接测试或字幕翻译失败；以服务实际返回的数据辅助选择，同时保留自定义输入，可覆盖标准服务与非标准部署。

**独立测试**：分别让 OpenAI 与 Ollama Endpoint 返回多个模型，确认下拉列表只展示响应中的有效模型；再输入响应中不存在的自定义 Model ID，保存、重新编辑并使用该 Profile，确认自定义值不被替换。

**验收场景**：

1. **假如** 当前 Endpoint 的模型列表返回多个有效模型，**当** 用户打开 Model ID 下拉列表，**那么** 用户可看到并选择这些模型，且列表中不存在产品预置的模型 ID。
2. **假如** 用户需要的模型未出现在已知列表中，**当** 用户选择自定义模型项并输入 Model ID，**那么** 该值可像已知模型一样保存、重新载入、测试和用于翻译。
3. **假如** 已保存或正在编辑的 Model ID 不在最新模型列表中，**当** 列表刷新完成，**那么** 当前值保持不变并作为自定义值呈现，不自动切换到其他模型。
4. **假如** 模型列表包含重复、空白或缺少有效 ID 的条目，**当** 列表呈现，**那么** 无效条目不显示，重复 ID 只显示一次。
5. **假如** 新建或编辑中的服务需要尚未保存的 API Key 才能列出模型，**当** 用户填写 Key 并手动刷新，**那么** 本次请求使用该 Key 返回已知模型，Key 不被保存、回显或用于自动刷新；用户选择模型后仍须显式保存完整 Profile。

---

### 用户故事 2：及时刷新当前 Endpoint 的模型（优先级：P1）

用户启动 IINA、打开 SubTandem 或改变服务 Endpoint 后，希望已知模型自动更新；也希望能在 Model ID 右侧手动刷新，以便立即看到服务端新增、删除或变更的模型。

**优先级理由**：模型目录会随远程服务状态变化；可靠的自动与手动刷新可避免使用陈旧列表，同时不能打断播放或覆盖用户正在编辑的选择。

**独立测试**：在 IINA 启动、SubTandem 打开、有效 Endpoint 变更及点击刷新按钮四种场景中改变服务端模型响应，确认每次都触发相应刷新；并让旧 Endpoint 的响应迟到，确认它不会覆盖当前 Endpoint 的列表或 Model ID。

**验收场景**：

1. **假如** IINA 启动时已有可访问的已保存 Profile，**当** SubTandem 首次能够执行后台刷新，**那么** 对应服务的已知模型会自动更新，且原始播放不被等待或失败阻塞。
2. **假如** 用户打开 SubTandem，**当** 当前 Profile 或新建表单具有格式有效的 Endpoint，**那么** 系统自动请求该 Endpoint 的最新模型列表。
3. **假如** 用户把 Endpoint 改为另一个格式有效且输入已稳定的地址，**当** 地址变更生效，**那么** 系统为新地址发起刷新，不继续把旧地址的结果当作当前列表。
4. **假如** 用户点击 Model ID 右侧的刷新按钮，**当** 请求完成，**那么** 列表使用本次响应更新，并在所属区域显示成功或安全分类后的失败反馈。
5. **假如** 刷新失败、响应无效或服务不可访问，**当** 结果返回，**那么** 当前 Model ID 与上次成功获得的列表保持可用，用户仍可使用自定义模型项，且失败不会自动改变 Profile 选择或翻译状态。
6. **假如** 同一编辑上下文发生多次刷新且结果乱序返回，**当** 较旧请求最后到达，**那么** 它不得覆盖较新 Endpoint、凭据上下文或手动刷新得到的结果。

---

### 用户故事 3：使用 API Key 访问远程 Ollama（优先级：P1）

用户连接需要认证的远程 Ollama 服务时，希望为 Ollama Profile 提供可选 API Key，并让模型刷新、连接测试和字幕翻译都使用该凭据，同时保持现有凭据的只写与隔离边界。

**优先级理由**：缺少凭据支持会使受保护的远程 Ollama 无法完成模型发现和翻译；凭据安全边界必须与现有服务一致。

**独立测试**：对要求 API Key 的远程 Ollama 分别使用正确、缺失和错误凭据执行模型刷新、Test 与翻译，确认正确凭据可完成全部操作，认证失败被安全分类，且凭据不会回显或进入持久偏好、日志、诊断和安装包。
另分别打开 OpenAI 与 Ollama Profile 编辑器，确认 API Key 主标签和只写/可选说明按其他配置项的纵向字段样式分行显示。

**验收场景**：

1. **假如** 远程 Ollama 要求 API Key，**当** 用户为 Profile 保存正确凭据，**那么** 模型刷新、Test 和翻译均使用该凭据并可成功访问服务。
2. **假如** Ollama 服务无需认证，**当** 用户不填写 API Key，**那么** Profile 仍可保存、刷新模型、测试和翻译。
3. **假如** API Key 缺失或错误，**当** 服务拒绝请求，**那么** 用户看到不包含凭据或原始敏感响应的认证错误，并可更换凭据后重试。
4. **假如** 用户重新编辑已保存的 Ollama Profile，**当** 表单载入，**那么** 只显示凭据已配置状态，不回显已保存的 API Key。
5. **假如** 用户删除 Ollama Profile，**当** 删除成功，**那么** 其凭据与 Profile 一同清理，且其他 Profile 的凭据不受影响。
6. **假如** 用户编辑 OpenAI 或 Ollama Profile，**当** API Key 配置项呈现，**那么** “API key” 主标签与只写、无需认证时可选的说明分别独占一行，并与页面其他配置项使用一致的纵向字段布局。

---

### 用户故事 4：以 OpenAI 名称配置兼容服务（优先级：P2）

用户在界面和当前产品文档中看到简洁一致的 OpenAI 服务类型名称，同时仍能把自定义 Endpoint 指向兼容 OpenAI 契约的本地或远程服务。

**优先级理由**：名称简化应提升可读性，但不能缩小用户可连接的服务范围或破坏已有 Profile。

**独立测试**：检查新建、编辑、列表、提示和当前用户文档中的服务名称均为 OpenAI；再载入既有 OpenAI-compatible Profile 并使用自定义 Endpoint 完成模型刷新、Test、Select 和翻译。

**验收场景**：

1. **假如** 用户创建或编辑对应服务 Profile，**当** 服务类型及其默认 Profile 名称呈现，**那么** 可见名称为 “OpenAI”，不再显示 “OpenAI-compatible”。
2. **假如** 用户选择 OpenAI 服务类型，**当** 用户填写有效的自定义 HTTP(S) Endpoint，**那么** 可保存并用于模型刷新、Test、Select 和翻译，不被限制为 OpenAI 官方地址。
3. **假如** 升级前已有该类型的 Profile，**当** 用户升级并打开 SubTandem，**那么** Profile 仍可编辑和使用，仅可见服务名称更新为 OpenAI。

### 边界情况

- 模型列表成功返回零个有效模型时，已知模型区域为空，但自定义模型项始终可用；不得用静态模型填充空列表。
- 列表中的模型 ID 可能包含大小写、数字、标点、命名空间或版本标签；除去首尾空白外不得改写服务返回的有效 ID。
- Endpoint 为空、格式无效或仍在连续输入时不得持续发起无效刷新；界面应保留当前 Model ID 并等待有效输入或手动操作。
- 用户快速切换 Service type、Profile 或 Endpoint 时，每个响应只能更新其所属的当前上下文；已离开的上下文不得污染当前列表。
- 手动刷新与自动刷新重叠时，用户发起的较新刷新结果具有当前性；重复请求不得造成重复选项或重复错误。
- 凭据刚被替换、删除或保存失败时，后续模型刷新必须使用权威凭据状态，迟到结果不得把旧凭据上下文标记为成功。
- 用户修改尚未保存的 API Key 时，使用旧输入凭据的草稿刷新必须立即失效；草稿目录不得跨凭据代次、窗口或请求复用。
- 保存新 Profile 后，权威创建结果必须立即进入当前窗口的 Profile 列表；凭据刷新必须取代保存前已被取消的同上下文模型请求，旧列表或模型结果不得恢复保存前状态。
- Ollama Endpoint 可能不支持 JSON Schema 或 `think` 参数；系统必须只发送服务支持的可选能力，并在无 structured outputs 时继续通过严格提示与响应校验完成 Test 和翻译。
- 模型列表请求不得携带字幕、译文、播放位置或其他翻译正文；错误反馈不得包含 API Key、授权头或未清洗的服务响应。
- 模型目录只能说明 Endpoint 声明了某个模型，不能保证该模型支持字幕翻译；现有 Test 仍是验证可用性的独立步骤。

## 需求

### 功能需求

- **FR-001**：产品中该服务类型的用户可见名称必须由 “OpenAI-compatible” 统一改为 “OpenAI”，包括新建与编辑表单、默认 Profile 名称、Profile 列表、操作反馈和当前用户文档。
- **FR-002**：OpenAI 服务必须继续接受用户配置的有效 HTTP(S) API Root，并用该 Endpoint 完成模型发现、Test、Select 和翻译；不得限制为 OpenAI 官方服务。
- **FR-003**：升级前保存的对应 Profile 必须继续可见、可编辑和可使用；名称调整不得改变其 Endpoint、Model ID、凭据状态、网络路线、选择同意或翻译语义。
- **FR-004**：OpenAI 与 Ollama 的 Model ID 控件必须由零个或多个已知模型选项和一个始终可选择、可编辑的自定义模型选项组成；用户选择过任意已知模型后仍必须能切换到自定义输入，并明确区分两种模式。
- **FR-005**：已知模型只能来自当前 Service type 与 Endpoint 的模型列表响应，不得内置、猜测或在空响应和失败时补入任何模型 ID。
- **FR-006**：系统必须从模型列表响应中提取非空模型 ID、去除完全重复的 ID，并保留每个有效 ID 的原始大小写与内容。
- **FR-007**：选择已知模型或输入自定义模型后，Model ID 必须继续作为 Profile 的单一模型选择保存；刷新不得自动选择第一个模型，也不得替换用户当前选择。
- **FR-008**：当当前 Model ID 未出现在最新已知列表中时，系统必须将其保留并按自定义值呈现；保存、Test 和翻译继续以该精确值为准。
- **FR-009**：系统必须在 IINA 启动后首次具备安全刷新条件时、用户打开 SubTandem 时，以及当前 Service type 的 Endpoint 变为稳定且格式有效的新值时自动刷新已知模型；刷新不得阻塞原始播放或打开 SubTandem 的基本操作。
- **FR-010**：Model ID 右侧区域必须提供只显示刷新图标且具有可访问名称的手动刷新按钮；按钮的忙碌、成功和失败状态必须归属于当前模型区域，不得替换 Profile 选择、Test、保存或其他操作的反馈。
- **FR-011**：自动或手动刷新失败时，系统必须保留当前 Model ID、上次成功获得的已知列表和自定义输入能力，并提供经过安全分类的可操作反馈；失败不得改变当前选择、授权字幕外发或触发翻译。
- **FR-012**：只有当前 Service type、Endpoint、Profile 与凭据上下文的最新刷新结果可以更新当前模型列表；重复、取消、迟到或已失去上下文的结果不得覆盖较新结果或清除较新反馈。凭据保存成功后的刷新必须取得新请求所有权，不得与保存前已被取消的自动刷新合并。
- **FR-013**：不同 Service type、Endpoint 和 Profile 的已知模型数据必须彼此隔离；列表不得跨上下文合并或误用。
- **FR-014**：模型刷新请求必须使用当前网络路线。自动刷新和未提供草稿凭据的手动刷新只可使用完全匹配当前已保存 Profile 的权威凭据；用户在 API Key 输入框填写非空值后手动刷新时，系统必须只为该次草稿模型请求使用该未保存 Key。所有刷新均不得包含字幕、译文、播放位置或其他翻译正文。
- **FR-015**：OpenAI 模型列表不得依据响应条目的 `owned_by` 筛选。
- **FR-016**：Ollama Profile 必须提供可选的只写 API Key；未填写凭据不得阻止无需认证的本地或远程 Ollama 使用。
- **FR-017**：已保存的 Ollama API Key 必须用于该 Profile 的模型刷新、Test 和翻译，并沿用现有凭据保存、替换、状态展示与删除生命周期；跨越凭据保存或替换边界的旧 Provider 构造结果不得继续执行 Test 或翻译。Ollama Test 与翻译必须兼容不支持 structured outputs 的原生远程 API，不得强制发送不受支持的 `format` 或 `think` 参数，且响应仍须通过精确 ID 与非空译文校验。
- **FR-018**：Ollama API Key 保存后不得返回 Sidebar、回显给用户或进入 IINA preferences、日志、诊断、进程参数、安装包及无关 UI 状态；认证错误不得暴露凭据、授权头或未清洗的服务响应。
- **FR-019**：模型刷新不得选择 Profile、创建播放授权、改变现有选择或发送字幕；用户仍必须独立执行 Select 后才能将 Profile 用于字幕翻译。
- **FR-020**：自动化验证必须覆盖两种 Service type 的响应驱动列表、自定义 Model ID、全部刷新触发、空与无效响应、失败保留、竞态隔离、OpenAI 自定义 Endpoint 与名称、Ollama 有凭据和无凭据访问及敏感数据隔离；IINA 启动与打开 SubTandem 的宿主生命周期必须保留明确人工验收步骤。
- **FR-021**：OpenAI 与 Ollama 的 API Key 配置项必须使用与其他配置项一致的纵向字段布局；“API key” 主标签必须独占一行，只写与无需认证时可选的说明必须在单独一行显示，并与输入框建立可访问的说明关联。
- **FR-022**：Profile revision 创建成功后，当前窗口必须立即显示新建或更新后的安全 Profile view，并使创建前尚未完成的 Profile 列表响应失效；随后权威列表刷新可补充凭据与模型目录状态，但不得暂时移除已创建 Profile。
- **FR-023**：草稿凭据模型刷新必须由用户手动触发，使用独立严格消息且不得把 Key 写入响应、上下文摘要、模型目录缓存、preferences、日志、诊断或安装包；Endpoint、Service type、网络路线、输入 Key 或窗口请求所有权变化后，旧结果必须被拒绝。
- **FR-024**：完整 Profile 仍必须保存非空 Model ID；当用户在 Model ID 为空时点击保存，Sidebar 必须阻止无效请求，并指示用户刷新并选择已知模型或输入 Custom Model ID。

### 关键实体

- **Provider Profile**：用户保存的翻译服务配置，包含名称、Service type、Endpoint、Model ID、网络路线、revision 与凭据已配置状态；API Key 值不属于可读 Profile 状态。
- **模型目录**：某一 Service type、Endpoint、Profile 与凭据上下文最近一次成功返回的有效模型集合；其内容完全来自服务响应，可以为空，并与其他上下文隔离。
- **模型条目**：服务声明的模型，至少包含精确 Model ID。
- **模型选择**：Profile 当前保存的单一 Model ID，来源可以是已知模型条目或用户自定义输入；列表刷新不改变该值。
- **刷新上下文**：一次模型目录请求所属的 Service type、Endpoint、Profile、凭据状态、网络路线和请求时序，用于拒绝迟到或失效结果。
- **Provider 凭据**：与单个 Profile 关联的可选 API Key；OpenAI 与 Ollama 均遵守只写、隔离、替换和随 Profile 删除的生命周期。

## 成功标准

### 可度量结果

- **SC-001**：在两种 Service type 的模型目录验收中，界面展示的已知 Model ID 与当前有效响应中的全部有效 ID 匹配率为 100%，由产品预置或猜测产生的模型数量为 0。
- **SC-002**：对于在 3 秒内返回有效模型列表的服务，至少 95% 的自动或手动刷新在触发后 5 秒内向用户呈现更新结果；刷新期间原始播放被阻塞的次数为 0。
- **SC-003**：IINA 启动、打开 SubTandem、有效 Endpoint 变更和手动刷新四类触发的验收通过率为 100%；旧上下文或迟到响应覆盖当前列表的次数为 0。
- **SC-004**：已知模型选择、自定义模型输入和列表中已消失模型三类流程均可在首次尝试中正确保存并重新载入，刷新造成的 Model ID 意外变更次数为 0。
- **SC-005**：对要求认证的远程 Ollama，正确 API Key 下模型刷新、Test 和翻译的验收通过率为 100%；缺失或错误 Key 均产生安全认证反馈，凭据出现在回显、偏好、日志、诊断、进程参数或安装包中的次数为 0。
- **SC-006**：当前产品界面和用户文档中该服务类型的可见名称与 “OpenAI” 匹配率为 100%，遗留 “OpenAI-compatible” 可见名称数量为 0；升级前 Profile 的配置保持率为 100%。
- **SC-007**：模型刷新不发送字幕、不改变 Profile 选择且不授权翻译的安全回归通过率为 100%；不同 Endpoint、Profile 或窗口之间的模型目录串用次数为 0。

## 范围边界

- 本功能只调整现有 OpenAI 与 Ollama Service type，不新增第三种服务类型，也不改变 Profile 必须由用户明确 Select 后才能翻译的规则。
- OpenAI 是用户可见名称，不表示 Endpoint 只能属于 OpenAI 官方服务；兼容相同服务契约的自定义本地或远程 Endpoint 继续属于支持范围。
- 已知模型只用于辅助填写 Model ID，不负责判断模型是否支持 Chat、结构化输出、目标语言或字幕翻译，也不替代现有 Test。
- 本功能不下载、拉取、安装、删除或管理服务端模型，不提供 Ollama 模型 pull 操作。
- 本功能不提供 API Key 的创建、查询、轮换或远程撤销；只保存和使用用户明确提供的凭据。
- 本功能不持久化字幕或译文，不把模型刷新视为字幕外发同意，也不扩大模型列表请求的网络目的地到当前 Endpoint 之外。
- 模型目录可以短暂保留上次成功结果以承受刷新失败，但不得作为内置模型知识或跨 Endpoint 的兜底目录。

## 假设

- OpenAI 与 Ollama Endpoint 均提供各自兼容的模型列表能力；不提供该能力的自定义服务仍可通过自定义 Model ID 使用现有 Test 与翻译流程。
- 自动刷新只在 Endpoint 格式有效且相应界面或已保存 Profile 已具备所需上下文时执行；系统可以合并同一上下文中同时发生的等价自动刷新。
- Ollama API Key 为可选 Bearer 凭据；为空时不发送认证信息，适用于无需认证的本地或远程服务。
- 用户在 API Key 输入框填写的未保存 Key 只在手动模型刷新时作为一次性 Bearer 使用；自动刷新不得读取或发送该值。
- 上次成功获得的模型目录属于运行期辅助数据，不改变已保存 Profile 中 Model ID 的权威地位；重新启动后的列表仍需从服务响应刷新。
- 现有凭据存储与权限边界能够扩展到 Ollama，无需新增用户可读的密钥存储位置。
- 模型列表请求沿用 Profile 的 Endpoint 与网络路线，并遵守现有 URL、重定向、目的地、错误清洗和敏感数据隔离规则。
