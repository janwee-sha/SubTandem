# 研究：原生侧栏视觉与语言自动保存

## 目标语言提交触发

**决策**：移除显式保存控件，由 Target Language 的 `change` 事件在值不同于 committed 时立即复用 `defaults:save`。操作协调器把选择器作为 `languages` action 的 busy 控件，等待期间禁用，确保同一 Sidebar 只有一个 pending。

**理由**：既有 Main、Global、preference adapter 和消息 envelope 已提供严格校验、原子写入、revision 与 request ID 关联；改变触发点即可满足需求，且避免新增持久化契约。

**考虑过的替代方案**：保留隐藏按钮会留下无生产用途的旧路径；debounce 会使“选中即保存”的时机不明确；允许并发并建立 latest-only 队列会扩大现有单 pending 契约和测试面。

选择器在首次取得有效 committed 值和 revision 前保持禁用，避免 WebView 水合前使用默认 revision 发起保存；水合后由同一 busy 控件逻辑管理可操作状态。

## 失败与权威状态

**决策**：成功结果采用返回的 target language 和 revision，由选择器最终值承担可见确认，并通过视觉隐藏播报公布终态。匹配 pending 的失败、取消与 `operation:error` 均恢复 committed 值、清理 pending 并显示异常；不匹配的结果仍由操作协调器拒绝。状态快照只在未等待本地保存时对齐选择器。

**理由**：恢复 committed 能避免界面展示未生效的语言；等待时忽略旧快照能避免选择瞬间回跳；Global 继续是持久值的唯一权威。

**考虑过的替代方案**：失败后保留草稿需要新的重试入口，且移除保存按钮后用户难以理解如何重试；乐观切换翻译上下文会产生错误方向的短暂请求和额外回滚。

## 操作反馈分层

**决策**：请求身份与区域所有权保持不变，但普通操作的 busy 由原控件禁用、`aria-busy`、按钮文案或刷新图标表达；Translate、Target Language、Position、Profile Save/Update/Create/Select/Delete 与成功的 Subtitle Retry 以权威界面状态作为可见成功结果。其 busy 和成功文案只进入单一视觉隐藏播报槽。失败、回滚和 Profile 已保存但凭据未保存的部分成功仍就近可见。Profile Test 使用与 revision 绑定的卡片状态，模型刷新使用数量、空目录或失败领域状态。

**理由**：这些常规成功消息重复解释已经可见的控件状态，在窄侧栏内形成高对比长文本并推挤配置内容；Test 与模型目录却会影响后续决策，不能只靠按钮恢复 idle 表达。将两者建模为领域状态可同时减少噪声和保留关键信息。

**考虑过的替代方案**：按固定时间隐藏 toast 会增加计时与动态行为，且错误可能在用户阅读前消失；完全删除 live region 会降低辅助技术对异步提交结果的可感知性；继续让所有终态共享可见成功行会保留当前视觉冲突。

## 原生侧栏视觉层级

**决策**：WebView 根表面保持透明；宿主插件标签下不重复显示插件标题，Translate 与 Subtitle 共用首个 section 标题行。顶层 section 使用全宽平铺布局、20px 内容边距及 1px 语义分隔线。只为 Profile 集合与 Session 摘要保留低对比、10px 圆角的半透明填充，不增加嵌套 blur 或常驻外框；表单控件使用无常驻描边的透明语义填充、正常字重和 26px 高度，Model ID 的选择与编辑控件保持 5px 间距，系统开关使用 44×20px 轨道与 26×16px 胶囊形滑块。Position 保留 20px 命中区，但通过 WebKit track/thumb 伪元素固定为 3px 中性半透明轨道与 18×14px、7px 圆角的浅色矩形旋钮；旋钮不增加独立描边或投影，强制颜色模式回退系统绘制。

**理由**：IINA 侧栏主要由统一材质和分区构成，圆角材质只包裹强关联控件。现状给每个 section 添加高不透明卡片、阴影和描边，形成网页仪表盘层级，并放大了宿主差异。

**考虑过的替代方案**：在 WebView 内增加 blur 会与宿主材质叠加并强化网页卡片感；只设置 range 的 `accent-color` 会继续保留 WKWebView 的深色凹槽与偏大旋钮；完全仿制 IINA 原生控件会依赖宿主未公开的 AppKit/vibrancy 能力；引入 UI 框架不符合本切片范围。

## 宿主能力边界

**决策**：不尝试修改 IINA 顶部插件切换条，也不声称 WebView 可取得与原生 AppKit sidebar 完全相同的动态材质。插件依赖宿主提供的透明 WebView 背景，并通过低对比透明语义色做降级友好的近似，不自行采样或硬编码视频颜色。

**理由**：插件只控制自己的 HTML/CSS；宿主切换条、WebView 合成层和原生 vibrancy 由 IINA 管理。把不可控差异写入验收会产生无法稳定维护的要求。

**考虑过的替代方案**：按当前视频截图硬编码暖色会在其他视频和系统外观下失真；依赖忽略的本地截图会违反版本化管理原则。

## 验证边界

**决策**：契约测试直接检查 DOM 中无保存按钮、选择事件唯一发送保存、控件内 busy、辅助技术播报、失败回滚、领域状态和关键视觉 token；完整类型、lint、测试和构建证明交付无回归。最终视觉由开发者在 IINA 亮色和暗色外观下按 quickstart 人工确认。

**理由**：自动化可证明结构和状态，无法证明 WKWebView 与宿主材质的最终合成观感；单人实机步骤符合人工成本约束。

**考虑过的替代方案**：只做截图文本匹配不能证明状态转换；未经批准使用浏览器控制或 Computer Use 不符合项目工作协议。
