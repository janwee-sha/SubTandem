# 功能规格：Provider 连接生命周期

**功能目录**：`specs/003-provider-connection-lifecycle`  
**创建日期**：2026-08-13  
**状态**：已完成
**输入**：修复远程 Profile 长视频翻译因上游并发或连接持续累积而中断的问题，并确保每次 Profile Test 都真实检查当前服务状态，同时维持网络路由、多窗口、取消和 helper 生命周期隔离。

## 用户场景与测试

### 用户故事 1：长视频翻译持续可用（优先级：P1）

用户使用已授权的远程 Profile 播放长视频时，希望 `system` 与 `direct` 路径的翻译请求都按服务主机有界执行并复用有限连接；同一 OpenAI-compatible Profile 的连续调用还应保持稳定的运行期会话身份，使第二字幕不会因播放时间或请求数量增加而耗尽连接或网关会话额度。

**优先级理由**：连接耗尽会直接中断核心翻译流程，并使继续播放无法自行恢复，是本功能必须先解决的用户影响。

**独立测试**：在远程 OpenAI-compatible `direct` 路径连续处理至少 100 个 cue 或持续播放 5 分钟，期间保持多个翻译请求；第二字幕应持续更新，同一 Profile 的全部请求保持一个运行期会话身份，且不会出现连接或网关会话耗尽。自动化同时覆盖 `system` 路径。

**验收场景**：

1. **假如** 用户已选择并授权一个远程 Profile，**当** 通过所选网络路径连续翻译至少 100 个 cue，**那么** 第二字幕持续产生，连接和网关会话使用保持在规定上限内，且不发生耗尽。
2. **假如** 同一服务主机同时存在多个翻译请求，**当** 请求陆续完成并继续产生新请求，**那么** 每个主机同时进入传输层的请求不超过 4 个，后续请求复用有限的现有连接。
3. **假如** 一个请求被取消，或系统代理请求发生允许的重定向，**当** 其他请求仍在执行，**那么** 只有目标请求的状态发生变化，其他请求继续独立完成。
4. **假如** 用户选择 `direct` 路径，**当** 连续请求同一服务，**那么** helper 复用有界连接，同时保持绕过代理、取消、错误和安全行为不变。
5. **假如** OpenAI-compatible 网关按客户端会话限制容量，**当** 同一 Profile 连续执行 Test 和两条一组的翻译请求，**那么** 所有请求使用同一个仅在本次运行期有效的会话身份，不因每批字幕内容不同而持续占用新会话。

---

### 用户故事 2：Profile Test 反映当前服务状态（优先级：P2）

用户点击 Profile 的 Test 时，希望每次操作都实际连接当前配置的服务，而不是因先前已缓存 capability 直接报告成功。

**优先级理由**：假成功会掩盖配额、认证、模型或网络的当前故障，使用户在正式翻译时才发现问题。

**独立测试**：先让一个 Profile 成功发现并缓存 capability，再让服务返回 429；随后点击 Test，必须产生新的联网检查并显示当前配额错误，而不是沿用历史成功结果。

**验收场景**：

1. **假如** Profile 已缓存可用 capability，**当** 用户再次执行 Test，**那么** 系统仍至少发起一次真实服务请求，并只根据本次响应给出结果。
2. **假如** capability 已缓存而服务当前返回 429，**当** 用户执行 Test，**那么** Test 失败并报告既有配额错误分类和用户行动，不返回历史成功。
3. **假如** 同一窗口或不同窗口并发执行 Test，**当** 某个 Test 完成、取消或所属 Profile 被删除，**那么** 每次 Test 只结束自己的活动检查，不影响其他 Test 或翻译请求。
4. **假如** 当前播放窗口已选择一个 Profile，**当** 用户测试任意 Profile，**那么** Test 不改变任何窗口的播放选择或授权状态。

---

### 用户故事 3：生命周期操作继续互相隔离（优先级：P3）

用户在多个 IINA 窗口中翻译、测试、取消或关闭时，希望每个窗口和每项任务只管理自身资源，helper 启动与关闭也不留下可继续影响其他工作的连接或结果。

**优先级理由**：连接共享不能以破坏现有多窗口身份、取消精度、关闭清理或敏感数据边界为代价。

**独立测试**：让两个窗口以可能相同的外部请求 ID 并发翻译和测试，取消或关闭其中一个窗口；另一个窗口应继续工作，迟到结果对已关闭窗口的写入为 0，helper 关闭后不再接受新请求且活动连接全部释放。

**验收场景**：

1. **假如** 两个窗口同时使用同一 Profile，**当** 一个窗口取消请求或结束播放，**那么** 另一个窗口的翻译、Test、缓存和第二字幕不受影响。
2. **假如** 两个窗口产生相同的消息请求 ID，**当** 两项工作并发运行，**那么** 结果仍只路由到所属窗口，取消也只作用于所属任务。
3. **假如** helper 开始关闭，**当** 尚有活动上游请求，**那么** 它们被终止并完成清理；关闭开始后不再接受新的上游请求。
4. **假如** 已取消、已完成或已关闭任务随后收到网络回调，**当** 回调到达，**那么** 它不会再次完成任务、修改窗口状态或产生跨窗口结果。

### 边界情况

- 同一主机超过 4 个上游请求同时排队时，等待请求必须保持各自身份，取消其中一个等待请求不得占用连接或取消其他请求。
- 一个请求在完成与取消同时发生时，只能产生一个终态；重复取消继续使用现有稳定状态。
- 同源重定向次数超过既有限制或跳往跨源目标时，只有对应请求失败，其他共享会话请求继续工作。
- capability 发现过程中收到认证、模型、配额或网络错误时，不得通过尝试其他 capability 掩盖该错误。
- Profile 被修订或删除时，旧 revision 的活动 Test 和翻译必须失效；其他 Profile 及其他窗口不受影响。
- helper 正常空闲退出、显式关闭或父进程退出时，共享会话、等待队列和活动请求均不得遗留为可继续回调的工作。
- OpenAI-compatible 服务忽略未知扩展 header 时，请求必须保持兼容；接受 `X-Session-Id` 时，同一 Provider 运行时的 Test 与翻译必须复用该身份。

## 需求

### 功能需求

- **FR-001**：`system` 与 `direct` 路径必须在同一 helper 生命周期内复用有界连接；系统代理路径使用共享会话，`direct` 使用有界 easy handle 池，避免连接总量随请求数量持续累积。
- **FR-002**：两条路径对同一服务主机同时进入传输层的请求不得超过 4 个；超过上限的请求必须等待可用许可且保持自身任务身份。
- **FR-003**：每个上游请求必须拥有独立的活动身份、取消入口和终态，取消、完成或失败一个请求不得改变其他请求的状态。
- **FR-004**：每个请求的重定向计数与原始目的地必须按任务隔离，并继续拒绝跨源或超过既有次数限制的重定向。
- **FR-005**：helper 关闭必须停止接收新的上游请求、取消等待与活动请求并释放共享会话资源；关闭后的迟到回调不得产生第二次终态。
- **FR-006**：`direct` 路径必须继续显式绕过系统代理，在相同 origin 的后续请求间复用有限连接，并保持现有取消、超时、响应大小、重定向和目的地限制行为。
- **FR-007**：每次 Profile Test 必须创建唯一的连接测试任务，并至少执行一次针对当前 Profile revision 的真实联网检查。
- **FR-008**：已缓存 capability 只能决定本次检查采用的请求格式，不得作为跳过联网或直接判定成功的依据。
- **FR-009**：Profile Test 必须继续使用现有认证、模型、配额、超时、网络、配置和协议错误分类；当前 429 必须报告为配额错误。
- **FR-010**：Profile Test 的完成、取消和 Profile 删除必须只作用于匹配的测试任务；并发 Test 与翻译任务必须互相隔离。
- **FR-011**：Profile Test 不得选择 Profile、修改任何窗口的当前播放选择或授权翻译，也不得改变 Test 与 Select 的独立语义。
- **FR-012**：本功能不得改变 helper RPC、Global/Main/Sidebar 消息名称与字段结构。
- **FR-013**：同一 OpenAI-compatible Provider 运行时的 Profile Test 与翻译请求必须携带同一个无业务语义的 `X-Session-Id`；该身份只在内存中存在，不得包含 Profile、窗口、字幕、endpoint 或凭据内容，也不得进入 UI、日志、持久化或跨运行时消息。
- **FR-014**：本功能不得改变每逻辑批次 25 个 cue、每次 wire 最多 2 个 cue 或失败后最多三次额外重试的既有边界。
- **FR-015**：本功能不得新增持久化状态、恢复按钮、网络目的地、日志内容、字幕外发范围或凭据流向。

### 关键实体

- **上游连接生命周期**：同一 helper 生命周期内两条路径共同使用每主机请求门控；系统代理请求共享瞬时传输会话，`direct` 使用有界 easy handle 池复用连接。
- **活动请求**：一次上游调用的瞬时身份，关联所属任务、取消入口、终态和必要的重定向状态。
- **连接测试任务**：一次用户触发的真实 Profile Test，关联窗口、消息请求、内部唯一身份、Profile revision 和终态，但不代表播放选择。
- **Provider 运行期会话**：一个 OpenAI-compatible Provider 实例拥有的无业务语义瞬时身份，供该实例的 Test 与翻译请求共同复用；它不是 helper job、播放窗口或持久会话。

### 范围边界

**范围内**：系统代理共享会话、`direct` 有界 easy handle 池、两条网络路径的每主机请求上限与连接复用、OpenAI-compatible Profile 运行期会话身份、按任务取消与系统路径重定向状态、helper 关闭清理、Profile Test 真实连接接口、Global 中测试任务隔离，以及相应自动化和正式包验收。

**范围外**：统一 `system` 与 `direct` 的底层传输实现、修改 RPC 或 UI 消息格式、改变翻译批次/wire/重试策略、新增恢复 UI 或持久化连接状态、扩大网络或敏感数据边界。

## 成功标准

### 可度量结果

- **SC-001**：通过远程 OpenAI-compatible `direct` Profile 连续处理至少 100 个 cue 或播放 5 分钟时，第二字幕持续输出，因连接或网关会话耗尽导致的中断次数为 0。
- **SC-002**：在同一服务主机存在超过 4 个并发请求的 `system` 与 `direct` 压力场景中，观测到的同时传输请求最大值均为 4，且全部未取消请求最终得到各自终态。
- **SC-003**：已缓存 capability 后执行 Test 的每次操作均产生至少 1 次真实服务请求；服务当前返回 429 时，假成功次数为 0，结果为既有配额错误分类。
- **SC-004**：多窗口并发、单项取消、Profile 修订/删除和窗口关闭场景中，跨窗口结果、跨任务取消和迟到状态写入次数均为 0。
- **SC-005**：helper 关闭后新上游请求的接受次数为 0，关闭前活动请求均进入唯一终态，连接资源全部释放。
- **SC-006**：同一 OpenAI-compatible Provider 实例的连续 Test 与翻译请求全部携带同一个运行期会话身份，不同实例的身份不相同，身份进入持久化、UI、日志或跨运行时消息的次数为 0。
- **SC-007**：`direct` 的 no-proxy、安全与错误行为、消息结构、25 cue/batch、2 cue/wire、最多三次额外重试以及 Test/Select 独立语义的回归断言全部通过。

## 假设

- 用户已具有可正常保存和授权的 Provider Profile；本功能不改变 Profile 的凭据或 revision 模型。
- capability 仍可作为非敏感 Profile 元数据保存，但只用于选择兼容的请求格式。
- 系统代理由 macOS 当前环境提供；功能不新增代理配置入口，也不改变目的地校验。
- 每个 helper 仍由现有 Global 生命周期管理；共享会话和请求门控仅存在于该 helper 进程内，不跨进程或宿主会话持久化。
- 实机验收使用用户自行准备且可合法用于测试的本地视频与外挂字幕；媒体路径、字幕正文、凭据和 provider 原始响应均不得写入证据。
