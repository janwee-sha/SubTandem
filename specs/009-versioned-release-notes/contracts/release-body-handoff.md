# Release 正文传递契约

## 发布准备

1. 用户明确目标稳定版本及对应的一项或多项规格。
2. 维护者确认指定范围已经实现并验收，创建或更新 `docs/releases/vX.Y.Z.md`。
3. 发布说明与版本变更一起进入触发自动发布的提交；发布准备不得把 commit、PR 或 issue 当作未指定的功能范围来源。

## 自动流程接口

| 阶段 | 输入 | 输出与约束 |
| --- | --- | --- |
| 元数据 | 项目版本与仓库中的版本化发布说明 | 先验证正文契约，输出 `release_notes_path` 与 `release_notes_sha256`；失败时不进入昂贵构建。 |
| 构建与审计 | 元数据输出、八项门禁、最终安装包与技术审计输入 | 在全部构建步骤后重新验证正文并核对初始摘要；原样复制到 `build/release/release-notes.md`，把源路径与摘要写入 `release-audit.json`。 |
| 跨任务传递 | `build/release/` 工作流产物 | 用户正文副本、审计 JSON、安装包和校验材料作为同一个只读产物传给发布任务；该产物不回写仓库。 |
| 发布 | 审计产物、版本、tag 和触发提交 | 在任何远端写入前复验正文结构、摘要及审计身份；使用正文副本创建或恢复 draft。 |

发布任务不得根据 commit、PR、issue、审计 JSON 或其他输入拼接、删改或重新生成正文。

## 技术证据分离

- `release-notes.md`：审计后的用户正文副本，只作为 GitHub Release body 输入，不作为公开附件。
- `release-audit.json`：保留安装包、门禁、归档、helper、FFmpeg、正文摘要和 IINA 宿主未覆盖状态。
- Actions 摘要与日志：显示同一审计记录的维护者视图。
- 公开资产：继续只有安装包、安装包校验、锁定 FFmpeg 源码和源码校验；不得因本功能新增技术证据附件。
- `.iinaplgz`：内容和白名单不变，不包含版本化发布说明或审计材料。

## 远端状态决策

| 远端状态 | 正文与身份 | 结果 |
| --- | --- | --- |
| 不存在 Release，tag 不存在 | 本地正文有效 | 为触发提交创建 draft。 |
| 不存在 Release，tag 指向触发提交 | 本地正文有效 | 验证既有 tag 后创建 draft。 |
| 不存在 Release，tag 指向其他提交 | 任意 | 冲突失败，不写入。 |
| 稳定 draft | target、规范化正文和已有资产均一致 | 恢复 draft，只补齐缺失资产。 |
| draft 为 prerelease 或任一身份/正文/资产冲突 | 任意 | 冲突失败，不覆盖、不删除。 |
| 已公开稳定 Release | 规范化正文一致 | 安全跳过，不比较同版本后续触发提交，不修改远端对象。 |
| 已公开稳定 Release | 规范化正文不一致 | 报告正文冲突，tag、正文和资产修改次数均为零。 |
| 已公开 prerelease | 任意 | 冲突失败。 |

并发创建后若读取到已公开 Release，仍按公开版本正文一致性决定跳过或冲突。

## 公开前后核对

- draft 公开前必须再次确认 target、规范化正文和四项资产完整一致。
- 新版本公开后必须确认非 draft、非 prerelease、tag 指向本次触发提交、正文一致、四项资产完整且 Release 为 Latest。
- 相同版本后续执行只读跳过时，既有 tag 可以继续指向首次发布提交，但必须仍存在且正文一致。
- 任一核对失败不得删除 tag、Release 或资产，也不得使用覆盖选项。
