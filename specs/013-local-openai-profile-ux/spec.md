# 功能规格：Provider HTTP 与 Profile 交互优化

**功能目录**：`specs/013-local-openai-profile-ux`  
**创建日期**：2026-08-20  
**状态**：已完成

**输入**：允许所有 Service type 配置本地或远程 HTTP endpoint，由用户自行承担明文传输风险，SubTandem 不以远程 HTTP 不安全为由阻止配置；同时修复 Profile 删除后的界面滞留，使操作消息在所属区域就近显示且全局只保留最新一条，优化 Profile 默认名称和翻译选择文案，并将版本更新为 0.1.0。

## Clarifications

### Session 2026-08-20

- Q: HTTP 明文传输风险说明应显示在哪里？ → A: 不必在任何位置说明风险。
- Q: 为同时允许所有远程 HTTP 且不说明风险，如何处理现行宪法的用户披露要求？ → A: 宪法应明确该条文只适用于 SubTandem 本身的产品逻辑；用户自定义行为不在此范围。

## 用户场景与测试

### 用户故事 1：为任意 Service type 配置 HTTP 服务（优先级：P1）

用户选择只提供 HTTP 的翻译服务时，希望无论该服务属于哪种 Service type、位于本机还是远程网络，都能直接保存、测试、选择并用于字幕翻译。用户自行判断并承担明文 HTTP 可能造成的窃听、篡改、凭据或字幕泄露风险；SubTandem 提供配置与使用途径，不以 endpoint 位于远程网络或未使用 HTTPS 为由从根源上阻止用户。

**优先级理由**：强制远程服务使用 HTTPS 会让用户无法使用其明确选择的 HTTP 服务，并把产品的安全偏好变成不可绕过的能力限制；把最终选择交还用户是本次变更的核心能力。

**独立测试**：对产品提供的每种 Service type，分别使用回环、局域网或私网以及公网主机上的有效 HTTP endpoint 创建 Profile，并验证保存、Test、Select 和实际翻译均可完成，且不会仅因 endpoint 使用远程 HTTP 而被拒绝。

**验收场景**：

1. **假如** 任一 Service type 的服务在有效 HTTP 地址提供兼容能力，**当** 用户填写该 Service type 所需的 endpoint、模型及可选凭据并保存，**那么** 无论主机位于本机、局域网、私网还是公网，Profile 都可保存并执行 Test、Select 和翻译。
2. **假如** 用户填写非回环 HTTP endpoint，**当** 用户保存或使用 Profile，**那么** SubTandem 不得仅因连接未使用 HTTPS 或主机位于远程网络而拒绝操作、要求改用 HTTPS 或限制可配置的主机范围。
3. **假如** 用户主动配置并选择 HTTP Profile，**当** SubTandem 向该 endpoint 发送翻译请求，**那么** 该操作按用户选择执行，明文传输产生的安全风险由用户承担，且不需要额外的强制确认步骤。
4. **假如** 用户使用 HTTPS endpoint，**当** 用户保存、测试、选择或翻译，**那么** 现有行为保持不变。
5. **假如** HTTP endpoint 格式错误、使用非 HTTP(S) scheme、包含 URL 凭据或片段，或者请求试图跨来源重定向，**当** 用户保存或使用 Profile，**那么** 仍按对应的既有规则拒绝，不因允许远程 HTTP 而放宽与明文传输无关的边界。

### 用户故事 2：删除后立即看到最新 Profile 列表（优先级：P1）

用户确认删除 Profile 后，希望对应条目在删除成功时立即从当前界面消失，并同步清理与该 Profile 相关的编辑、选择和测试状态。

**优先级理由**：删除成功但条目仍显示会让用户误以为数据没有删除，并可能继续操作已失效的 Profile。

**独立测试**：删除一个当前可见且分别处于未选择、已选择、正在编辑或已有 Test 状态的 Profile；收到删除成功结果后，条目应立即消失，相关状态应清理，后续列表刷新也不得让其重新出现。

**验收场景**：

1. **假如** 用户确认删除一个现有 Profile，**当** 删除成功结果返回，**那么** 对应条目立即从当前 Profile 列表移除，无需等待定时刷新或重新打开 Sidebar。
2. **假如** 被删除 Profile 当前已选择或正在编辑，**当** 删除成功，**那么** 当前选择被清除，编辑器回到新建状态，相关 Test 状态不再显示。
3. **假如** 删除失败或用户取消确认，**当** 操作结束，**那么** Profile 条目和既有状态保持可见，并在删除操作区域下方显示对应结果。
4. **假如** 删除成功后发生列表同步或重新打开 Sidebar，**当** Profile 列表再次呈现，**那么** 已删除条目不会重新出现。

---

### 用户故事 3：在发起操作的位置读取结果（优先级：P2）

用户执行界面操作时，希望进度、成功、失败或取消消息出现在对应操作控件所在区域的正下方，同时页面始终只保留最新一条操作消息，直到下一条有效消息替换它，避免不同区域残留的旧消息造成误解。

**优先级理由**：就近且全局唯一的反馈能让用户立即判断哪项操作正在发生，并避免多个 Profile 或会话区域同时保留已经失去上下文的消息。

**独立测试**：依次及交错执行翻译开关、语言保存、Profile 保存或更新、Profile 选择、Test、删除及字幕重试；每条运行中或最终消息只出现在所属控件区域，写入时立即替换所有其他区域的消息，并保持可见直至下一条被接受的消息写入。

**验收场景**：

1. **假如** 页面包含多个可操作区域，**当** 用户发起一项操作，**那么** 该操作的运行中消息显示在对应控件区域正下方。
2. **假如** 操作成功、失败或取消，**当** 最终结果返回，**那么** 最终消息替换同一区域的运行中消息并保持在该区域，不迁移到其他功能区域。
3. **假如** 任一区域当前存在操作消息，**当** 另一区域产生新的运行中或被接受的最终消息，**那么** 旧消息立即清除，页面只显示新消息。
4. **假如** 一条运行中或最终消息已经显示，**当** 没有新的被接受消息写入，**那么** 该消息保持可见；只有下一条被接受的消息才能替换它。
5. **假如** 未知、重复或已失去所属区域最新请求身份的结果到达，**当** 页面正在显示其他消息，**那么** 该结果既不显示消息，也不清除当前消息。
6. **假如** 一项操作来自某个具体 Profile 条目，**当** 操作产生反馈，**那么** 消息显示在该条目的对应操作控件正下方，而不是其他 Profile 或公共编辑器下方。

---

### 用户故事 4：使用 Service type 作为默认 Profile 名称（优先级：P2）

用户创建 Profile 时，希望名称默认使用当前 Service type 的可见名称，从而无需先删除无关的通用占位名称，同时仍可输入自定义名称。

**优先级理由**：合理默认值减少创建步骤，并让未自定义的 Profile 在列表中仍具有明确含义。

**独立测试**：进入新建状态并切换不同 Service type；未手动改名时，Profile name 应跟随当前 Service type 名称，手动输入自定义名称后切换类型不得覆盖该名称。

**验收场景**：

1. **假如** 用户进入新建 Profile 状态，**当** 页面显示默认 Service type，**那么** Profile name 默认等于该 Service type 的可见名称。
2. **假如** Profile name 仍是系统提供的默认值，**当** 用户切换 Service type，**那么** Profile name 更新为新 Service type 的可见名称。
3. **假如** 用户已手动修改 Profile name，**当** 用户切换 Service type，**那么** 自定义名称保持不变。
4. **假如** 用户编辑既有 Profile，**当** 编辑器载入，**那么** 保存的 Profile 名称保持不变，不被 Service type 默认值覆盖。

---

### 用户故事 5：获得简洁一致的翻译选择提示（优先级：P3）

用户更新或测试 Profile 后，希望提示统一说明选择该 Profile 即可用于翻译，不再使用容易与权限授权混淆的 “authorize translation” 表述。

**优先级理由**：一致文案能准确表达 Select 的用途，并与现有凭据授权概念区分。

**独立测试**：触发 Profile 更新导致选择失效和 Test 成功，并检查全部用户可见文案；指定消息必须精确匹配，且不再出现 “to authorize translation”。

**验收场景**：

1. **假如** 更新 Profile 后需要重新选择，**当** 更新成功，**那么** 显示 “Profile updated. Select it again for translation.”。
2. **假如** Profile Test 成功，**当** 结果显示，**那么** 显示 “Connection test passed. Select this profile for translation.”。
3. **假如** 其他用户可见提示仍含有 “to authorize translation”，**当** 0.1.0 版本准备完成，**那么** 这些提示统一改为使用 “for translation” 表达相同含义。

### 边界情况

- HTTP endpoint 的主机可以是回环、局域网、私网、公网域名或公网 IP；这些网络位置不得成为拒绝配置或使用的理由。
- endpoint 仍必须是格式有效的完整 HTTP(S) URL；允许远程 HTTP 不代表允许非 HTTP(S) scheme、URL 内嵌凭据、片段或其他既有禁止内容。
- HTTP endpoint 发生重定向、改变来源或尝试改变授权目的地时，必须继续受既有重定向与目的地限制；允许初始远程 HTTP endpoint 不等于授权新的目标。
- HTTP 服务经代理或直接网络路线访问时，协议与主机范围的允许规则必须一致，不得因网络路线不同重新施加仅限 HTTPS 或仅限回环的限制。
- 删除成功结果重复到达或删除条目已因同步消失时，界面必须保持稳定，不得重新创建条目或显示错误对象。
- Profile 列表同步与删除成功结果顺序交错时，最终界面必须以已持久删除的状态为准。
- 同一区域的新操作开始后，旧操作的迟到结果不得产生或清除反馈；任一区域写入新操作消息时必须立即清除所有其他区域的消息，全局同时可见的操作消息不得超过一条。
- 操作消息不得按时间自动清除；同一 request 的终态消息替换运行中消息，其他区域的新消息替换当前消息。
- Profile name 为空、仅含空白或用户清空默认值时，保存仍按既有名称校验处理，不将占位文字误当成已输入名称。
- 文案统一只改变用户可见措辞，不改变 Profile 更新后需要重新选择以及 Test 不自动选择 Profile 的既有语义。

## 需求

### 功能需求

- **FR-001**：产品提供的所有 Service type 必须允许用户配置并使用有效的 HTTP 或 HTTPS endpoint。
- **FR-002**：HTTP endpoint 的主机可以位于回环、局域网、私网或公网；保存、Test、Select 和翻译不得仅因 endpoint 使用 HTTP、位于非回环地址或可由远程网络访问而拒绝操作、要求 HTTPS 或施加主机白名单。
- **FR-003**：用户配置并选择 HTTP Profile 后，SubTandem 必须按该选择发起请求，不得增加阻断使用的强制安全确认；明文传输的保密性、完整性与服务身份风险由用户承担。
- **FR-004**：允许远程 HTTP 不得放宽 URL 格式、非 HTTP(S) scheme、URL 凭据、片段、重定向目的地、凭据流向、日志或字幕外发范围的既有限制；这些限制必须对 HTTP 与 HTTPS 一致执行。
- **FR-005**：Profile 删除必须在权威删除成功结果返回后立即从当前列表移除对应条目，不得依赖后续定时列表刷新完成当前界面更新。
- **FR-006**：Profile 删除成功必须同步清理该 Profile 的当前选择、编辑器内容、凭据状态展示与 Test 状态；删除失败或取消不得清理这些状态。
- **FR-007**：删除成功后的后续列表同步必须保持已删除状态；重复或迟到结果不得恢复条目或破坏其他 Profile 状态。
- **FR-008**：每项用户发起操作的运行中及最终反馈必须显示在对应操作控件所在区域正下方，以可访问方式公布，并保持可见直至下一条被接受的操作消息替换它。
- **FR-009**：所有操作区域必须共享全局消息竞态；任一区域写入新的运行中或被接受的最终消息时，必须立即清除其余区域的现有消息，使全局同时可见的操作消息最多一条。请求结果仍只能写入其所属区域，未知、重复或迟到结果不得显示消息、清除当前消息或覆盖同一区域较新的请求。
- **FR-010**：新建 Profile 时，Profile name 必须默认等于当前 Service type 的可见名称。
- **FR-011**：当名称仍由系统默认生成时，切换 Service type 必须同步更新默认名称；用户自定义名称及既有 Profile 名称不得被自动覆盖。
- **FR-012**：Profile 更新并使选择失效后的成功文案必须精确为 “Profile updated. Select it again for translation.”。
- **FR-013**：Profile Test 成功文案必须精确为 “Connection test passed. Select this profile for translation.”。
- **FR-014**：全部用户可见生产文案中不得再出现 “to authorize translation”；对应语义必须统一使用 “for translation”，且不得改变 Select、Test 或凭据授权行为。
- **FR-015**：项目用户版本、包元数据、正式归档身份及发布所需版本引用必须一致更新为 0.1.0。
- **FR-016**：本功能的自动化验证必须覆盖所有 Service type 的本地与远程 HTTP 许可、保留的 URL 与数据安全边界、删除即时更新与竞态、反馈归属、全局消息竞态、消息持久显示与替换、默认名称保护、文案和版本一致性；跨运行时与宿主界面行为必须保留明确的人工验收步骤。

### 关键实体

- **Provider Profile**：用户保存的翻译服务配置，包含名称、Service type、endpoint、模型、网络路径、revision 与凭据已配置状态；凭据值仍不属于可读界面状态。
- **Provider endpoint**：用户为某一 Service type 配置的完整 HTTP(S) 服务地址；协议和主机网络位置不限制 Profile 的保存与使用，其他既有 URL 与数据边界继续适用。
- **操作反馈**：与一次用户操作及其界面区域关联的运行中或最终消息；请求归属按区域隔离，但可见消息在全局互斥，并由下一条被接受的消息替换。
- **Profile 默认名称**：由当前 Service type 可见名称派生、可被用户自定义覆盖的新建表单值。
- **删除结果**：确认 Profile 已持久删除的权威结果，用于同步当前列表和相关瞬时界面状态。

## 成功标准

### 可度量结果

- **SC-001**：对产品提供的每种 Service type，回环、局域网或私网及公网上的有效 HTTP Profile，其保存、Test、Select 和翻译验收通过率均为 100%，因远程 HTTP 或未使用 HTTPS 导致的拒绝次数为 0。
- **SC-002**：删除成功结果返回后 1 秒内，对应 Profile 条目消失率为 100%，无需等待定时刷新；随后列表同步和重新打开 Sidebar 时重新出现次数为 0。
- **SC-003**：覆盖全部现有用户操作区域的验收中，运行中及最终反馈位于发起区域正下方的比例为 100%；任意时刻同时可见的操作消息不超过一条，未被下一条有效消息替换时保持可见，迟到结果误清除或覆盖当前消息的次数为 0。
- **SC-004**：所有 Service type 的新建流程中，未自定义名称与可见 Service type 名称匹配率为 100%；自定义名称和既有名称被意外覆盖次数为 0。
- **SC-005**：指定的 Update 与 Test 成功消息精确匹配率为 100%，用户可见生产文案中 “to authorize translation” 的剩余出现次数为 0。
- **SC-006**：项目与正式安装包中的用户版本一致为 0.1.0，版本不一致项和新增非必要包内容均为 0。
- **SC-007**：所有 Service type 的本地与远程 HTTP、现有 HTTPS Provider、凭据隔离、跨来源重定向拒绝、Profile revision、Test/Select 独立语义和多窗口隔离回归全部通过。

## 范围边界

- 本功能允许当前产品提供的所有 Service type 使用本地或远程 HTTP endpoint，包括回环、局域网、私网与公网目标；不再以远程 HTTP 不安全为由限制配置或使用。
- 用户主动配置并选择 HTTP Profile 即表示接受明文传输风险；SubTandem 不承诺 HTTP 连接的保密性、完整性或服务身份，也不负责为该服务提供 HTTPS、VPN、代理或其他传输保护。
- 本功能以修订后的项目宪法为治理前提：只有 SubTandem 自身产品逻辑主动扩大网络目的地时才触发用户披露要求；用户自行填写、保存并选择 endpoint 属于用户自定义行为，不在该条文范围。重新规划 013 前必须先完成这项宪法修订。
- 不新增 Service type，不改变各 Service type 的请求格式、模型能力发现、批次、重试或翻译选择语义。
- 不改变凭据的保存位置、可读范围、权限或生命周期，不把 endpoint、凭据、字幕或响应内容新增到日志与诊断信息。
- 即时删除更新只在权威成功结果返回后发生，不把用户点击确认视为删除已经成功。
- 操作反馈调整不改变操作结果分类、请求执行、控件 busy 或权威业务状态，只改变消息归属、全局可见竞态、持续显示、位置和本功能明确列出的措辞。
- 版本更新目标仅为 0.1.0；正式发布、推送、创建 tag 或修改 GitHub Release 不属于本规格实施范围。

## 假设

- “所有 Service type”指本功能发布时产品提供且允许用户配置 endpoint 的全部翻译服务类型。
- 用户了解 HTTP 不提供 HTTPS 所具有的传输保护，并有权根据自己的网络环境和风险判断决定是否配置；规格不要求增加额外确认步骤。
- 服务可选择无需凭据；若对应 Service type 要求凭据，继续使用既有只写凭据流程。
- Service type 的可见名称是用户理解该类型的权威默认名称；用户一旦手动编辑 Profile name，系统即视为自定义值。
- Profile 删除只有在持久化和凭据清理均按现有删除契约成功后才返回权威成功结果。
- “所有消息”仅指 Translate、Target Language 选择器自动保存、Profile Save/Update 与 Credential 终态、Profile Select/Test/Delete、Subtitle Retry 的操作反馈；Session 状态、Profile 元数据、凭据已配置状态和静态说明不参与全局消息竞态。
- 操作消息不设置自动清除计时；同一 request 的运行中消息由终态替换，随后保持可见直至下一条被接受的消息写入。
