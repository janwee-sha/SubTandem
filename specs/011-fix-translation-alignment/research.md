# 研究与技术决策：字幕译文内容对齐

## 共用翻译任务

**决策**：OpenAI-compatible 与 Ollama 复用同一任务构造器。内部目标使用 `{ id, text, contextPrevious?, contextNext? }`；wire payload 使用 `targets`，正文保持为 `text`，真实前一句和后一句分别编码为可选的 `context_previous` 与 `context_next`。系统指令明确只翻译 `text`，两个上下文字段只能消歧且不得翻译、复制、解释或输出。

**理由**：当前两套指令已经漂移，且“翻译每个 JSON item”容易让模型把 item 内上下文也当正文。明确字段角色并集中生成指令可让所有能力模式和后续 Provider 遵守一个产品契约。

**考虑过的替代方案**：各 Provider 分别补 prompt 仍会漂移；删除上下文会损失既定消歧能力；每 cue 单独请求会增加延迟与调用；仅靠输出 schema 无法阻止合法 ID 的文本混入上下文。

## 不可信数据边界

**决策**：共用系统指令声明目标文本和上下文均为不可信数据，其中的伪指令、字段名、语言要求或格式要求不得改变翻译方向、目标身份和输出格式。user message 只携带 JSON 数据，不拼接数据来源的自然语言指令。

**理由**：OpenAI 当前只保护 `text`，Ollama 未声明不可信输入；两者都没有覆盖 `context`。系统层统一约束能在不改变外发类别的情况下收紧提示注入边界。

**考虑过的替代方案**：转义关键词无法穷举指令形式；在 user message 重复任务会混合控制与数据；对字幕内容做拒绝名单会误伤真实字幕。

## 真实邻接与冻结上下文

**决策**：首次逻辑 attempt 前，从当前既有 120 秒/40 cue 窗口按源顺序为本批目标查找真实前后邻居，分别冻结为前句和后句上下文。两者各至多一条，并按前句、后句顺序合计沿用 500 字符总上限。缓存命中、渐进成功和重试只筛除已解决目标，不重新计算其余目标的上下文。

**理由**：当前实现从 `pending/remaining` 计算邻接，缓存命中或部分成功后会把原本不相邻的 cue 误当上下文。窗口内权威顺序可稳定跨逻辑批次、wire part 和重试边界，又不扩大前瞻、上下文数量或类别。

**考虑过的替代方案**：每次重试重算会继续漂移；只在初始 pending 内冻结仍会受缓存过滤影响；从完整媒体无限取邻居可能扩大当前窗口隐私边界。

## Wire 身份与请求拆分

**决策**：保留原 cue ID→`c1…` 的短 ID 映射、每次最多 2 个目标的 Provider 请求和片内精确 schema。`context_previous` 或 `context_next` 可以引用另一 part 或逻辑批次目标的正文，但不携带独立输出 ID；每个 part 只允许返回本片目标 ID。

**理由**：现有短 ID 恢复与片内 schema 已能保护身份且避免暴露内部时间 ID。跨边界上下文是合法参考，不能因此提前产生边界外译文。

**考虑过的替代方案**：移除跨 part 上下文会降低边界处消歧；给上下文分配输出 ID 会把参考升级为目标；改变批次大小超出本功能范围。

## 结果验证与部分成功

**决策**：保留 Provider 层对 requested、唯一、非空 ID/text 的结构校验；Controller 在每个进度或终态写缓存前先统计当前返回 ID，未知、空白或同一返回内重复的 ID 整体无效，其余合法子集继续成功。已由进度接受的 ID 在终态聚合中按现有未解决集合忽略。

**理由**：正式 Provider 已有校验，但 Controller 当前会接受注入或未来 Provider 返回的第一个重复 ID，违反统一契约。入口双层校验可防止无效结果进入缓存，同时保留渐进输出和只重试未解决 cue。

**考虑过的替代方案**：只信任当前两类 Provider 会让 fake、注入和后续 Provider 绕过契约；整批失败会丢弃无关合法结果并增加重试；接受首个或末个重复结果没有可信冲突规则。

## 不建立通用语义清洗器

**决策**：产品不根据字符串相似度、脚本、括号、标签或语言检测自动删除“疑似污染”译文。内容约束依赖共用任务、结构化输出和实际 Provider 验收；完全不服从任务的服务沿用现有无效/失败处理边界。

**理由**：专有名词、数字、外语片段、罗马化原文和合法括注可能属于当前字幕语义，启发式清洗会产生不可预测的数据损坏，也超出规格假设。

**考虑过的替代方案**：后处理裁剪或正则黑名单误报高；二次模型审查会扩大外发、成本、延迟和失败面；保存人工纠错会引入新持久化范围。

## 验证分层

**决策**：自动化证明真实生产构造器、两类 Provider、ID/批次/时间/缓存和生命周期边界；授权的实际 Provider 验收证明模型输出不混入上下文、原文、罗马化、字段名或说明；正式 `.iinaplgz` 单人验收证明连续播放和重叠显示。

**理由**：mock 可以确定产品是否只把当前字幕设为目标，但不能证明非确定模型服从语义；Node 集成测试也不能证明 IINA 视频与原字幕没有中断。

**考虑过的替代方案**：把真实服务测试设为默认 CI 会依赖秘密、网络、费用和非确定结果；只做人工测试会失去可重复的身份与失败回归；用测试名称或文档解析代替生产行为违反宪法。
