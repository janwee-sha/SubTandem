# 功能规格：字幕译文内容对齐

**功能目录**：`specs/011-fix-translation-alignment`

**创建日期**：2026-08-19

**状态**：已完成

**输入**：修复翻译结果混入相邻字幕、原文、罗马化文本、字段名或解释而造成的内容污染与时间错位，并对所有翻译服务采用一致行为。

## 用户场景与测试

### 用户故事 1：只看到当前字幕的译文（优先级：P1）

用户观看连续字幕时，希望每个时间范围内显示的译文只表达对应源字幕的内容；系统可以参考邻近字幕消除歧义，但不得把参考内容当作待翻译正文。

**优先级理由**：混入前后句或附加文本会直接造成阅读重复、剧情提前泄露和译文时间错位，破坏实时字幕翻译的核心价值。

**独立测试**：使用含有可明确区分的前句、当前句和后句的连续字幕，让翻译服务接收当前句及必要上下文；逐条核对显示内容、所属条目和时间范围，即可验证当前句是否获得干净译文。

**验收场景**：

1. **假如** 当前字幕前后都有不同内容的相邻字幕，**当** 当前字幕被翻译并显示，**那么** 译文只表达当前字幕正文，不包含前句或后句的译文。
2. **假如** 邻近字幕被作为消歧上下文提供，**当** 翻译服务处理当前字幕，**那么** 上下文不会成为额外译文，也不会以字段名、解释或其他元数据形式出现在结果中。
3. **假如** 当前字幕不需要罗马化或原文保留，**当** 有效译文显示，**那么** 系统不会无依据附加拼音等罗马化文本、源语言回显、语言标签、括注或翻译说明。
4. **假如** 当前播放位置同时命中多个真实重叠字幕条目，**当** 译文显示，**那么** 每条译文仍分别对应自己的源条目；按既有重叠字幕规则合并显示不被误判为上下文污染。

---

### 用户故事 2：切换服务仍保持一致对齐（优先级：P2）

用户切换任一受支持翻译服务时，希望字幕目标、上下文用途和返回内容遵循同一规则，不因服务类型、批次拆分或模型差异而改变。

**优先级理由**：统一契约可避免相同缺陷在其他服务或后续新增服务中重现，并让用户无需理解各服务的内部差异。

**独立测试**：对每类受支持翻译服务发送相同的连续字幕集合，覆盖单条、多条、无上下文和跨请求边界上下文，核对每个结果只对应其请求 ID 与当前字幕正文。

**验收场景**：

1. **假如** 用户选择任一受支持翻译服务，**当** 同一组字幕被翻译，**那么** 每类服务都把当前字幕正文视为唯一翻译目标，并把邻近字幕仅视为消歧参考。
2. **假如** 一个逻辑批次被拆成多个服务请求，且某条字幕的上下文包含另一个请求中的字幕，**当** 各请求返回，**那么** 任何结果都不会提前或重复输出其他请求所负责字幕的译文。
3. **假如** 源字幕正文或上下文包含类似指令、字段名或格式要求的文字，**当** 服务处理请求，**那么** 这些内容仍被视为待处理数据，不能改变翻译目标、语言方向或输出约束。
4. **假如** 后续增加新的翻译服务类型，**当** 其用于字幕翻译，**那么** 它必须满足同一目标与上下文语义，不能以服务专用例外改变用户可见结果。

### 边界情况

- 当前字幕位于首条或末条、因而只有单侧上下文或完全没有上下文时，仍只翻译当前字幕正文。
- 当前字幕为多行文本、包含标点、专有名词、数字或必须保留的源语言片段时，应忠实翻译当前内容；不得仅因结果中出现这些合法内容而判定污染。
- 相邻字幕文本完全相同或部分重复时，每个结果仍按请求 ID 归属，不得丢失、合并或写入错误时间范围。
- 上下文在批次或服务请求边界之外时，只能辅助当前字幕消歧，不能触发边界外字幕的提前翻译或显示。
- 服务返回缺失、重复、未知 ID、空白文本或无法解析的内容时，继续沿用无效结果处理，不得把其缓存或显示为成功译文。
- 翻译延迟、失败或结果无效时，视频与原字幕继续播放，不显示占位文本、技术错误或错配译文。

## 需求

### 功能需求

- **FR-001**：每个送往翻译服务的字幕条目 MUST 明确且仅有一个待翻译正文，并以该条目的身份关联唯一结果。
- **FR-002**：邻近字幕 MAY 仅在消除指代、词义或语境歧义所必需时作为上下文提供；真实前一句与后一句 MUST 保持为两个方向明确的可选上下文，不得拼接为无法区分方向的字段；上下文 MUST NOT 被视为待翻译正文或独立输出目标。
- **FR-003**：所有受支持翻译服务 MUST 遵循相同的待翻译正文、上下文用途、语言方向、条目身份和输出内容约束；产品 MUST NOT 以某个服务或模型的专用规则定义这些语义。
- **FR-004**：每条成功结果 MUST 只包含对应当前字幕正文的目标语言译文，MUST NOT 无依据新增相邻字幕译文、源语言回显、罗马化文本、字段名、语言标签、解释或翻译说明。
- **FR-005**：字幕正文与上下文 MUST 始终被视为不可信数据，MUST NOT 改变翻译任务、语言方向、请求内其他条目的归属或结果格式约束。
- **FR-006**：逻辑批次被拆分为多个服务请求时，每个返回结果 MUST 仍只对应本次请求内具有相同身份的待翻译字幕；上下文引用 MUST NOT 造成边界外字幕提前、重复或错位输出。
- **FR-007**：系统 MUST 保持成功译文与源字幕条目的一对一身份映射、原有顺序和时间范围；只有源字幕本身在当前时间真实重叠时，多个独立译文才可同时显示。
- **FR-008**：缺失、重复、未知身份、空白或不可解析的结果 MUST NOT 作为成功译文缓存或显示；失败处理 MUST NOT 阻塞视频或原字幕播放。
- **FR-009**：本功能 MUST NOT 扩大字幕前瞻范围、上下文数量、外发数据类别、诊断内容或字幕与译文的保留期限。
- **FR-010**：新增翻译服务类型 MUST 在用于用户字幕前证明满足本规格的统一语义与结果约束，MUST NOT 依赖用户理解或配置服务专用的防污染行为。

### 关键实体

- **待翻译字幕条目**：一次翻译中的唯一目标，包含不透明身份、当前字幕正文及其原有顺序和时间范围。
- **消歧上下文**：当前字幕的真实前一句和真实后一句，分别作为方向明确、仅用于理解指代或词义的可选参考文本；不拥有输出资格，也不改变当前目标身份。
- **字幕译文结果**：与一个待翻译字幕身份一一对应的目标语言文本；成功结果只表达该字幕正文，并沿用其显示时间范围。
- **翻译服务契约**：所有受支持服务共同遵循的目标、上下文、语言方向、身份映射和结果内容规则。

### 范围边界

**范围内**：

- 统一所有受支持翻译服务对待翻译正文与消歧上下文的理解。
- 约束每条译文的内容、身份和跨请求边界行为。
- 覆盖连续字幕、重叠字幕、多行字幕、批次拆分及不可信文本场景。

**范围外**：

- 新增翻译服务、模型推荐、服务配置界面或服务专用选项。
- 扩大上下文、前瞻和重试范围，或改变请求调度、会话缓存与生命周期。
- 改变译文覆盖层的样式、位置、换行和真实重叠字幕的合并显示规则。
- 评价或保证服务对词义、语气和文风的主观翻译质量，以及修正与上下文污染无关的模型事实错误。

## 成功标准

### 可衡量结果

- **SC-001**：在至少 100 条带有可区分前后文的连续字幕验收集中，100% 的成功译文只表达所属当前字幕，混入相邻字幕译文的条目数为 0。
- **SC-002**：对每类受支持翻译服务分别覆盖有上下文、无上下文、多条请求和跨请求边界场景时，100% 的成功结果保持正确身份、顺序和时间范围，提前、重复或错位条目数为 0。
- **SC-003**：在至少 100 条成功译文中，无依据新增的罗马化文本、源语言回显、字段名、语言标签、括注解释或翻译说明出现次数为 0。
- **SC-004**：含至少 20 个批次拆分边界和 20 个源字幕真实重叠区间的验收中，上下文造成的边界外输出为 0，真实重叠译文的丢失或错误归并为 0。
- **SC-005**：在至少 30 分钟连续播放并完成至少 100 条字幕翻译时，因本功能导致的视频暂停、原字幕中断或跨会话译文污染次数均为 0。
- **SC-006**：单名开发者按明确步骤切换每类受支持翻译服务并连续检查至少 20 条译文时，能够在全部场景中确认显示内容只对应当前源字幕，无需采用服务专用配置或人工清理输出。

## 假设

- 受支持翻译服务能够遵循明确、统一的结构化翻译任务；服务完全不遵循任务时沿用现有失败或无效结果处理，不在本功能中建立通用语义审查系统。
- 邻近字幕上下文仍可用于提高指代和词义消歧质量，但本功能不扩大当前最少必要上下文的隐私边界。
- 源字幕本身要求保留的专有名词、数字、外语片段或罗马化内容属于当前字幕语义，不视为服务无依据新增的污染。
- 现有字幕条目身份、时间轴、有限前瞻、批次调度、会话缓存、覆盖层渲染和生命周期隔离继续作为依赖，本功能只收紧翻译服务的共同语义与结果边界。
